# Task 1.1: macOS OpenGL Rendering — Replace SSBOs with Buffer Textures

Status: **implemented in `AlloyClient` and confirmed rendering on macOS; Windows/Linux spot-check still pending**
Depends on: [`01-macos-compatibility.md`](01-macos-compatibility.md)
Design doc reference: [`TRAINER_DESIGN.md` §9](../TRAINER_DESIGN.md#9-cross-platform-support-windows--macos)
Repos touched: `AlloyClient` only (no server changes)

## Why this exists

Task 01 covered the audio path bug and verified the server stack on macOS.
It did **not** anticipate this: the client's core renderer crashes on
launch on macOS because of a real GPU-API ceiling, not a config bug.
Confirmed on this machine (Apple Silicon, current macOS):

```
GL_VERSION: 4.1 Metal - 90.5
GLSL_VERSION: 4.10
GL_MAX_UNIFORM_BLOCK_SIZE: 65536
GL_MAX_TEXTURE_BUFFER_SIZE: 268435456
```

Apple's OpenGL implementation is a compatibility shim ("OpenGL via
Metal") capped at **OpenGL 4.1 Core / GLSL 410**, no matter what version
the app requests (`Main.cs` requests `new Version(4, 6)` — macOS silently
hands back 4.1 instead of erroring). Four shaders use
`readonly buffer` blocks (Shader Storage Buffer Objects), which require
OpenGL **4.3+**. SSBOs do not exist at all in a 4.1 context — this isn't
missing data or a wrong path, the GPU feature itself isn't there.

This is why the client currently crashes:
- **Debug builds**: segfault (`SIGSEGV` at a null function pointer) in
  `Alloy.Engine/GameWindow.cs`'s `EnableDebugOutput()` calling
  `GL.DebugMessageCallback`. macOS's GL 4.1 shim doesn't support
  `GL_KHR_debug`, so the extension loader binds the function pointer to
  null and the call crashes outright instead of throwing a catchable
  error on resolve.
- **Release builds** (where `EnableDebugOutput` is stripped by
  `[Conditional("DEBUG")]`): get further, then fail compiling
  `Ground.vert` / `Object.vert` with GLSL version/syntax errors, because
  the actual context is 4.1/410 but the shaders declare `#version 460
  core` and use `buffer` blocks that don't exist below 430.

## The fix: buffer textures instead of SSBOs

The codebase already has a working, mac-compatible pattern for small
per-frame instance data: `Alloy.Engine/Graphics/Buffers/UniformBuffer.cs`,
used today for shadows (`Shadow.vert`'s `layout(std140) uniform
ShadowData`). Its constructor caps size at `ushort.MaxValue + 1` bytes —
that cap is **exactly** `GL_MAX_UNIFORM_BLOCK_SIZE` on macOS (65536,
confirmed above), which strongly suggests whoever wrote it already hit
this macOS ceiling once before.

Problem: UBOs are capped at 64KB and that's nowhere near enough for the
three buffers that actually need replacing:

| Buffer | Struct | Instance count | Total size | Fits in 64KB UBO? |
|---|---|---|---|---|
| `Shadow.vert` (`ShadowData`) | 16 bytes | 4096 | 65,536 B | Yes — **already a UBO, leave as-is** |
| Particle (`Render.Particle.cs`, `ParticleData`) | 32 bytes | 2000 | 64,000 B | Yes, barely — could become a UBO |
| UI Sprite (`Ui.vert`, `SpriteInstanceData`) | 112 bytes | 1000 | 112,000 B | **No** |
| Ground/Tile (`Ground.vert`, `TileData`) | 80 bytes | 35,840 (`Map.VisibleChunks * TileMap.ChunkArea * 4`) | ~2.87 MB | **No** |
| Object/Entity (`Object.vert`, `VertexObject`) | 128 bytes | 10,000 | 1.28 MB | **No** |

So UBOs only solve Shadow (already done) and maybe Particle. The other
three need a real replacement for SSBO-style "arbitrary-size structured
array readable by index in a shader." The standard, portable fix — and
the one that fits inside GL 4.1 Core (buffer textures are core since GL
3.1) — is a **buffer texture** (`GL_TEXTURE_BUFFER` + `samplerBuffer` +
`texelFetch`). `GL_MAX_TEXTURE_BUFFER_SIZE` on this Mac is 268,435,456
bytes (256MB), comfortably covering all three buffers above with huge
headroom.

### What changes

1. **New buffer class** (`Alloy.Engine/Graphics/Buffers/`, alongside the
   existing `StorageBuffer.cs`): wraps a `GL_TEXTURE_BUFFER`-target
   buffer object + an associated texture object (`GL.TexBuffer`) bound to
   it, format `RGBA32F` (or `RGBA32UI` where a field needs bit-exact
   `uint`/color data — see `floatBitsToUint`/`uintBitsToFloat` note
   below). Keep the same `SetData`/constructor shape as `StorageBuffer<T>`
   so call sites in `Render.cs`, `Render.Particle.cs`, and
   `SpriteRender.cs` don't need restructuring beyond the type name and
   bind call (`BindToIndex` → bind as a texture unit + sampler uniform
   instead of `GL.BindBufferBase(BufferTarget.ShaderStorageBuffer, ...)`).
2. **Shader changes** — replace each `layout(std140, binding = N)
   readonly buffer InstanceBuffer { InstanceData data[...]; }` block with
   a `uniform samplerBuffer InstanceBuffer;` (or `usamplerBuffer` if using
   `RGBA32UI`) and a helper function that does `texelFetch(InstanceBuffer,
   instanceId * FIELDS_PER_INSTANCE + fieldIndex)` once per `vec4`-sized
   field, then reassembles the struct. Every struct here (`TileData`,
   `VertexObject`, `ShadowData`'s sibling `ParticleData`, `SpriteInstanceData`)
   is laid out as consecutive `vec4`/16-byte fields already (check
   `[StructLayout(LayoutKind.Sequential, Pack = 1)]` on the C# side), so
   this is "N texelFetch calls instead of 1 struct index" — no data
   repacking needed, just more verbose shader read code. `SpriteInstanceData`
   has `uint Color`/`uint ColorOverride` packed inside otherwise-float
   data — if you use `RGBA32F`, bit-cast those two components with
   `floatBitsToUint(texelFetch(...).x)` on read and make sure the C# side
   writes them as reinterpreted floats (or just use `RGBA32UI` for that
   buffer and `uintBitsToFloat` on the float fields instead — pick
   whichever is less churn once you're in the code).
3. **Shaders to update**: `AlloyClient/AdditionalFiles/Ground.vert`,
   `AlloyClient/AdditionalFiles/Object.vert`,
   `Alloy.UiLib/AdditionalFiles/Ui.vert`. Also lower every shader's
   `#version` pragma that currently says `460`/`450` down to a version
   actually supported by macOS's 4.1 context — `#version 410 core` is the
   ceiling; audit for any other 4.2+-only syntax while you're in each
   file (binding qualifiers on non-buffer blocks are fine in 410 via
   `ARB_shading_language_420pack` which macOS does support, but don't
   assume — verify each shader still compiles after the version drop).
4. **`EnableDebugOutput()` in `Alloy.Engine/GameWindow.cs`**: guard the
   `GL.DebugMessageCallback`/`GL.DebugMessageControl` calls so they don't
   run when `GL_KHR_debug` isn't available, instead of relying on
   `[Conditional("DEBUG")]` alone (Debug builds on macOS will still hit
   this). Check for the extension string, or simply skip on
   `OperatingSystem.IsMacOS()`, before registering the callback.

### What does NOT need to change

- `Shadow.vert` / `UniformBuffer.cs` — already UBO-based, already works
  within the 64KB macOS limit.
- Server (`alloy-server`/`GameServer`/`AccountServer`) — none of this
  touches server code; confirmed fully working on macOS in Task 01.
- `Alloy.Audio` — Task 01's fix is separate and already verified working.

### How to verify the GL ceiling yourself

The crash only reproduces with a real GL context, so logging alone won't
show it. Quickest way to confirm context version and limits on a given
Mac: in `GameWindow.cs`, right after `GLLoader.LoadBindings(...)` and
before `EnableDebugOutput()`, temporarily add:

```csharp
Console.WriteLine(GL.GetString(StringName.Version));
Console.WriteLine(GL.GetString(StringName.ShadingLanguageVersion));
GL.GetInteger(GetPName.MaxUniformBlockSize, out int maxUbo);
GL.GetInteger(GetPName.MaxTextureBufferSize, out int maxTbo);
Console.WriteLine($"{maxUbo} {maxTbo}");
```

then `Environment.Exit(0)` right after, build+run once, read the console
output, and revert. Don't leave this in — it's purely diagnostic.

## Implementation notes

Beyond what's described above, the fix also had to replace everything else
GL 4.1 lacks, since the SSBO swap alone would only have moved the crash:

- All direct-state-access calls (`CreateBuffer`, `NamedBuffer*`,
  `CreateTexture`, `TextureStorage2D`, `BindTextureUnit`, `VertexArray*`,
  `CreateSampler`) → bind-based equivalents. Buffers upload via
  `CopyWriteBuffer` so they never disturb VAO state; texture uploads bind on
  a reserved scratch unit (`TextureUnits.Scratch`).
- `GetProgramInterface*` (GL 4.3) uniform-block lookup → `GetActiveUniformBlockName`
  plus explicit `UniformBlockBinding` (no `layout(binding)` in 4.1).
- GLSL: `flat out` qualifier order in `Shadow.*`; `mix(uint, uint, bool)` (4.50)
  in `Ui.vert` → ternary. Particle.vert also used an SSBO and was converted.
- Instance buffers bind to texture unit 14 (`TextureUnits.InstanceBuffer`);
  `Sampler.Bind` now rejects units ≥ 14.

## Definition of done

- [ ] `Ground.vert`, `Object.vert`, `Ui.vert` no longer use `buffer`
      blocks; instance data is read via `samplerBuffer`/`texelFetch`.
- [ ] A new buffer-texture-backed class exists alongside
      `StorageBuffer<T>` and is used by `Render.cs` (tile + entity
      buffers) and `Alloy.UiLib/Rendering/SpriteRender.cs` (sprite
      instance buffer).
- [ ] All shader `#version` pragmas are ≤ 410 and compile unmodified on
      macOS's 4.1 context (verify by actually launching on a Mac, not
      just on Windows/Linux).
- [ ] `EnableDebugOutput()` no longer crashes on macOS in a Debug build
      (either skips cleanly or the extension is detected as unsupported
      and skipped).
- [ ] Full session on macOS: launch client, connect (per Task 01's
      smoke-test flow), see Nexus fully rendered (ground tiles, objects,
      entities, UI), move around, enter a dungeon, confirm shadows and
      particles still render correctly (regression check — those two
      stay UBO-based and shouldn't need changes, but confirm nothing
      broke).
- [ ] Spot-check on Windows/Linux after the change — buffer textures and
      lowered shader versions must not regress rendering there. The
      `StorageBuffer<T>` → buffer-texture swap is a behavior change for
      *all* platforms, not a macOS-only code path, unless you choose to
      branch by OS (not recommended — one rendering path is simpler to
      maintain than two).
